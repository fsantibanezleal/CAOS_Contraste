# Requirements: the methods compared across the questions of the benchmark (task T2, the document and its contract)

Status: live

EARS (Mavin et al., RE'09, doi:10.1109/RE.2009.9). Every requirement names the gate that fails when it is violated. The step is
`data-pipeline/pipeline/benchmark/methods.py` (`python -m pipeline.benchmark.methods` from `data-pipeline/`); the document is
`data/derived/benchmark/methods-compared.json` (contract `benchmark-methods` 1.0.0, the producer side). The design is
[`design.md`](design.md); the adversarial checks are [`validation.md`](validation.md); the tasks (T3 renders the document on the Benchmark
page, T4 points the Introduction, Experiments and the technical report at it) are in [`tasks.md`](tasks.md).

## The page (task T3): the methods compared on the Benchmark page

The overview tab "Methods compared" ("Métodos comparados") is the fourth tab of the reading group; each question is a section of its case's tab
(`frontend/src/pages/Benchmark.tsx`, `frontend/src/pages/benchmark/MethodsCompared.tsx`, the model in `frontend/src/lib/methodsCompared.ts`). The page
reads the document and recomputes nothing: every number, every best mark and every reading is the document's. The page keeps six groups and no
group above six tabs (ADR-0071); the seventh group the design first drew was not made. The bar chart follows the shell's chart, which carries
the zoom, pan, crosshair, keyboard and data table of the interactive-visualization rubric; a run on generated data is labelled synthetic and a
run on the real record real (the card's provenance). The shell gate (`npm run gate`) walks the page at five sizes, both themes and both languages.
