\section{Reproducibility}
\label{sec:reproducibility}

\subsection{Code, data and environment}
\label{sec:repro-code}

The source of the manuscript, the experiment scripts, their outputs and the figure and table scripts are in the folder \texttt{manuscripts/reconciliation-against-reference-engines} of the repository \url{https://github.com/fsantibanezleal/CAOS_Contraste}, in release 1.00.000 of CAOS\_Contraste (tag \texttt{v1.00.000}), which holds every experiment output with the script that writes it, the max-T outputs included. % voice-ok: the product release, not a version of this text
The deterministic experiments are rerun by \texttt{experiments/run\_all.py} with an output folder under the temporary root: it runs the printed answers, the independent routes, the closed forms, the committed documents and the pair correlations again, loads each new output beside the committed \texttt{results\_*.json}, reports any difference, and writes the wall time of each run to \texttt{run-times.json}; with \texttt{--tm-python} it also runs the comparison with \texttt{transitionMatrix} in the environment that holds that package. The three long experiments, the size and power of the acceptance rules (\texttt{exp\_criterion.py}), the repeated comparisons with ORE (\texttt{exp\_ore\_replicates.py}) and the max-T comparator (\texttt{exp\_maxt.py}), are run one at a time with the commands at the head of each script; each records its own wall time in its output, and every random number they draw comes from a fixed seed, so a rerun reproduces the committed output exactly. The committed documents that the experiments read are in \texttt{data/derived} of the same repository: the documents \texttt{C04/published.json}, \texttt{C05/ldp-published.json}, \texttt{C05/sp-2010.json} and \texttt{sp-2011.json} for the printed answers, and \texttt{C12/*.json} for the exposure case, with the ORE reconciliation block of each variant. The pipeline functions that the experiments call are in \texttt{data-pipeline/pipeline/cases/c12}. The environment is \texttt{riskvalidation} 1.1.0 with SciPy 1.18.1, NumPy 2.4.6, QuantLib 1.44 and the Open Source Risk Engine 1.8.17.0 on CPython 3.13; the comparison with \texttt{transitionMatrix} runs in an environment with that package (0.5.1) and pandas, installed with the optional \texttt{transitions} extra of the engine. No raw Treasury file is needed: the exposure experiments rebuild the zero curve, the parameters and the book from the committed documents, and the rebuilt expected exposure reproduces the committed one to $\nRebuildGap$ USD.

\subsection{Commands and seeds}
\label{sec:repro-commands}

Each experiment is one script run from the repository root with the Python of the product's environment. The deterministic ones need no argument: \texttt{exp\_printed.py}, \texttt{exp\_routes.py} (seed $20261104$ for the random cases), \texttt{exp\_closedforms.py} (seed $20261104$), \texttt{exp\_committed.py} and \texttt{exp\_pairs.py} (seeds $2{,}000{,}000+r$). The size and power of the rules run with \texttt{exp\_criterion.py --reps \nCritReps\ --workers 10} (seeds $1{,}000{,}000+2r$ and $1{,}000{,}000+2r+1$), and the maximum-T comparison, on the same seeds and five of the seven conditions, with \texttt{exp\_maxt.py --reps \nMaxtReps\ --workers 4} (the 400,000 Gaussian draws of the bound use seed $20261107$); its repeat of the product's rule and of the pair-aware rule at the bound $3.18$ reproduces the counts of \texttt{exp\_criterion.py} exactly, and the script records whether it does. The repeated comparison with ORE runs with \texttt{exp\_ore\_replicates.py --variant <name> --reps <n> --first-seed 5000} and the environment variable \texttt{CAOS\_TEMP\_ROOT} (or \texttt{--work}) naming the folder for ORE's run directories; \texttt{--mta0} adds the diagnostic run, and \texttt{--first-seed 42 --reps 1} reruns the product's seed. The comparison with the package runs with \texttt{exp\_transition\_matrix.py} in its environment. \texttt{make\_numbers.py}, \texttt{make\_tables.py} and \texttt{make\_figures.py} write \texttt{numbers.tex}, \texttt{tables/*.tex} and \texttt{figures/*.pdf}; the manuscript is built with \texttt{pdflatex}, \texttt{bibtex} and two more passes. The prose quotes no result that is not a macro of \texttt{numbers.tex}, whose manifest in \texttt{experiments/numbers-manifest.json} gives the source file and key of every macro. The file \texttt{experiments/predictions.md} holds the predictions fixed before the repeated comparison with ORE, and \texttt{experiments/test\_results.py} checks the committed outputs against the committed documents of the product.

\subsection{Run times}
\label{sec:repro-times}

The scripts were measured on one machine (\nHardware). The printed-answer, route, closed-form, committed-document and pair-correlation experiments take \nTimePrinted, \nTimeRoutes, \nTimeClosed, \nTimeCommitted\ and \nTimePairs\ seconds. The size and power of the rules take \nTimeCriterion\ seconds for \nCritReps\ repetitions on \nWorkers\ worker processes. The repeated comparisons with ORE take \nTimeOreNet, \nTimeOreSingle\ and \nTimeOreCsa\ seconds for the netting set, the single swap and the 10-day collateralised variant with the diagnostic run, and a single ORE run takes \nOreSecondsMean\ seconds on average for the uncollateralised variants. The maximum-T comparison takes \nTimeMaxt\ seconds for \nMaxtReps\ repetitions on four worker processes, the number that the memory of the machine allowed. The comparison with the package takes \nTimeTM\ seconds. The longest experiments, the size and power of the rules (\nTimeCriterionMin\ minutes) and the maximum-T comparison (\nTimeMaxtMin\ minutes), take about thirty minutes or less when the workers have the machine to themselves; the output files are committed so that the figures and tables can be rebuilt without rerunning any of them.

Three properties of the runs matter for repeating them. The run times scale with the number of paths and of repetitions, linearly for the engine's simulation, and ORE's wall time depends on the number of samples, the number of report dates and the collateral variant, the 10-day collateralised variant with its diagnostic run being about twice as long as the uncollateralised ones; and they depend on the load of the machine, since the repeated comparisons ran on four worker processes and the size and power on ten. Every random number is seeded, so a rerun reproduces the committed outputs exactly for the deterministic experiments, and the ORE comparison at the product's seed reproduces the committed standardised differences to within \nSeedFortyTwoGap, the precision at which they are stored. And ORE's analytic can fail for lack of memory while the process still exits normally; the script checks that the exposure file exists and repeats the run with the same inputs and the same seed, so that a failed run is repeated and never replaced by another draw.
